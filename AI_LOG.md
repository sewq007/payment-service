# AI_LOG

## Инструменты и модели

- Модель: GPT-5 в режиме code assistant, окружение без доступа к сети.
- Стек генерации: итеративный подход «черновик → ручная правка → прогон тестов».
- Локально: Windows, Python 3.14.8, pip 26.2.1, VS Code, pytest + httpx.AsyncClient
  для интеграционных тестов.

## Ключевые запросы (сокращённо)

1. **Контекст:** «FastAPI + SQLAlchemy 2 async + SQLite, тестовое задание про платежи
   онлайн-школы: тарифы, промокод KVITTO10, рассрочка 3/6/12, идемпотентность,
   вебхуки со строгими переходами статусов. Нужны тесты pytest».
   **Что просил:** сначала — каркас проекта и модели, потом — эндпоинты, потом — тесты.
   Это дало возможность проверять слои по отдельности.

2. **Контекст:** «Распределение копеек в графике рассрочки: сумма должна точно
   совпадать с amount, остаток — в первые платежи».
   **Ответ:** базовая формула:
   `base = total // n; remainder = total - base * n;`
   `schedule = [base + 1] * remainder + [base] * (n - remainder)`.
   Проверено на 1 990 000 / 3 → `[663334, 663333, 663333]`.

3. **Контекст:** «Идемпотентность POST /payments по заголовку Idempotency-Key:
   повторный запрос должен вернуть 200 и тот же объект, не создавая дубль».
   **Ответ:** уникальный индекс на `idempotency_key`, предварительный SELECT,
   возврат через `JSONResponse(status_code=200, ...)` — чтобы FastAPI не перезаписал
   код ответа значением по умолчанию `201`.

## Слабые места и как исправлял

- **Код ответа при идемпотентном повторе.** Первая версия возвращала объект напрямую
  из эндпоинта, и FastAPI отдавал 201. Исправлено явным `JSONResponse(200, ...)`.
- **Сериализация ORM-объекта в JSONResponse.** `model_dump(mode="json")` нужен, чтобы
  `datetime` корректно сериализовался и не ломал ответ.
- **Валидация installment-логики.** Сначала проверял в хендлере, но корректнее —
  в Pydantic-модели через `model_validator`, тогда ошибки автоматически идут как 422
  в стандартном формате FastAPI.
- **Промокод.** Сравнение делал по `strip().lower()` — модель сначала предлагала
  точное совпадение, что нарушало требование регистронезависимости.
- **Скидка в копейках.** Модель один раз предложила `round()` с float — заменил на
  целочисленное `amount * percent // 100`, чтобы строго соблюсти «никаких float».
- **Тесты с асинхронным SQLite.** Потребовался `pytest-asyncio` с `asyncio_mode = auto`
  и подмена зависимости `get_session` через `app.dependency_overrides`.

## Дополнительные наблюдения (реальная среда)

- Среда: Windows, Python 3.14.8, VS Code, pip 26.2.1.
- `pydantic==2.9.2` не имел prebuilt wheel под Python 3.14 — pip пытался собрать
  `pydantic-core` из Rust-исходников и падал на отсутствии MSVC-линкера
  (`link.exe not found`). Решение: поднять требование до `pydantic>=2.13.0`,
  где есть готовые колёса под cp314.
- `SQLAlchemy 2.0.35` падал на `Mapped[int | None]` с
  `TypeError: descriptor '__getitem__' requires a 'typing.Union' object but received a 'tuple'`
  на PEP 604 union-типах. Апгрейд до 2.1.3 устранил проблему.
- `uvicorn[standard]` под Windows не ставит `uvloop` (он там не поддерживается) —
  работает на встроенном `asyncio` loop, для тестового задания разницы нет.
- Проверял API не только через `pytest`, но и руками в Swagger UI + curl,
  сверял арифметику в копейках (1 990 000 / 3 → `[663334, 663333, 663333]`).
- Из `tests/conftest.py` убрал кастомный `event_loop` fixture — `pytest-asyncio`
  в режиме `auto` сам управляет loop'ом; это устранило
  `DeprecationWarning` про redefined fixture.
- В `pytest.ini` добавлен `filterwarnings = ignore::DeprecationWarning`, чтобы
  не засорять вывод предупреждениями из Starlette/FastAPI под Python 3.14
  (это чужие warnings, не из нашего кода).
